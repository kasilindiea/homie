# 沙盒模块交接

当前任务只实现 App 本体与家具添加。沙盒保留独立导航入口，不包含场景、模型、渲染引擎或导入逻辑。

## 接入原则

沙盒页面的入口位于 `src/features/sandbox.ts`，主导航由 `src/main.ts` 管理。后续开发者在沙盒模块内实现自己的页面和交互，不改动登录流程及家具存储格式。切换页面时应销毁渲染循环、事件监听、WebGL 资源和订阅，避免后台耗电。

现有模块导出 `renderSandbox()` 与 `mountSandbox(container, context)`。后者接收 `getFurniture()` 和 `navigateToFurniture()`，并返回退出页面时执行的清理函数。主页面已经接入这两个生命周期接口。

界面文案通过 `src/i18n.ts` 的 `t()` 获取，当前语言通过 `getLocale()` 获取。后续沙盒界面也应支持中文和英文；家具名称、备注等用户内容保持原文。语言偏好独立保存在 `homie.locale.v1`，家具数据继续使用原有的 `homing.app.v1`，无需迁移或清空。

共享数据以 `src/domain.ts` 为准。`createAppStore()` 返回当前 App 的数据操作对象，`getState().furniture` 提供家具列表的副本；请复用主 App 的同一 store 实例，避免多个实例互相覆盖存储。沙盒所需数据通过模块入口传入。

家具记录包含：`id`、`name`、`type`、`room`、`model`、`notes`、`createdAt`、`updatedAt`。其中 `model` 当前是用户填写的品牌/型号文字，不是 3D 模型文件路径。将来新增模型引用、位置、旋转或尺寸信息时，应设计独立的场景模型和存储版本迁移，不能将现有文字字段直接当成模型资源。

## 边界

- `type` 当前为 `sofa / chair / table / bed / cabinet / light / other`。
- 只有已登录的开发者会话可以操作家具数据。
- 数据存储为本地版本 1，不包含跨设备同步或多人协作。
- 当前“导入”独立占位，尚未约定支持的文件格式。
- App 不模拟设备在线状态，现有家具均为手动记录。

## 后续验收

从添加页创建家具后，切换到沙盒应能读取新记录；从沙盒退出后，添加和账号仍可正常使用；反复切换页面不得重复创建渲染器或事件监听；手机系统返回操作应先关闭沙盒内部浮层，再返回添加页。
