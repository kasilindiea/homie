# 离家检查联调准备清单

2026-11-14 · 首条链路 `baseline_apartment` · 共享约定 v0.5

后端 GPT‑6.1 Sol 准备接口和模拟数据，前端 GPT‑6 Astra 负责产品页面及状态接线，建模 GPT‑6 Astra 负责资产、映射和运行时状态适配。下表为走查和后续验收项。接口建议见 [离家检查后端接口草案.md](./离家检查后端接口草案.md)，请求和响应见 [离家检查联调样例.json](./离家检查联调样例.json)。

## 1. 当前可用静态样例核对

JSON 中每个场景的 `steps` 为请求与预期响应。各场景从 `starting_from` 指定的前置场景主线末尾开始。同一场景的 `steps` 顺序应用，`expected_ui` 记录预期界面。带 `alternative_from` 的步骤从指定场景的指定 `after_step`（从 1 开始）或独立 `setup` 启动。阳台无历史分支从首读即离线的会话独立开始。超时后仍读到 on 的分支从超时响应开始。

## 2. 与页面稿、建模 fixture 的差异

1. **离线与过期。** 当前 `offline` 的 `balcony_door` / `bedroom_ac` 仍把 `closed` / `on` 放在当前 `state`，空调还保留当前遥测，均无独立历史字段。`stale` 的客厅灯仍为 `on`。按 v0.5，适配后当前枚举归 `unknown`，失效的温度和剩余时间归 `null`。现行《离家检查前端设计与预留》要求有可核验的历史才展示。后端样例使用基线已核验的门磁读数，给出 `last_known_state`、`last_known_at` 和建议的 `last_known_source`，另有独立的无历史分支。当前 provider 归一化可产生 `last_known_values.state` 和 `last_known_at`，保留原 `source`，桥接输出归一化快照。生成历史形状只是现有行为，展示仍需核验同一条历史的来源与时间。
2. **本人出门与人工确认。** DS 原稿「我已确认关闭 · 现在出发」把两件事放在一条文案里。v0.5 下分别提交与反馈，玄关确认或稍后核实只影响该检查点。当前 13 个小公寓 fixture 中 `user_away` 均为 `false`、`occupancy` 均为 `occupied`、`manual_records` 均为空。`doors_open` 的人工观察可用于状态渲染走查，现场确认关闭和人工待办使用本轮样例。
3. **空调候选。** DS 原稿 A3 的「关灯」按共享语义修正为「关闭卧室空调」，接口动作 `turn_off`，目标 `off`，默认未勾选。
4. **回读超时与视觉。** DS 原稿 C3 提及 `unknown` 或 `failed`，超时按 v0.5 为 `unknown`，明确拒绝或失败证据归 `failed`。DS 原稿 C5 验收条件将熄灯写成「confirmed 且对象 off」，3D 及设备详情以有效对象 off 读数为准，包括外部关灯。任务面板用 `confirmed` 标记原执行完成。现行前端稿已明确两种到达顺序，本轮补独立联调用例。
5. **快照与计划。** `baseline` 的预置计划有灯、空调和玄关三项，后端基线生成样例带阳台 `check`，本轮补同一行刷新和无该行时的只读卡两种走查。部分状态画面 fixture 沿用基线计划，执行前仍按最新证据重新生成或复核。能源指标采用 `energy.measurements`，历史或兼容投影只用于展示。电池 `room_id=null`。页面稿引用的 `app/data.js` 未在当前工作区找到，前端确认真实入口和遗留字段映射。
6. **可另行复用的查看器场景。** `lights_left_on`、`doors_open` 用于定位与开合视觉，`off_but_powered`、`power_cut` 区分开关和供电，`ac_temperature` 验空调当前温度、设定值和定时分别更新，`low_backup` 验 15% 对 30% 及备电回路约束。`execution_failed` 可单独验拒绝文案。前端稿与本轮样例都以建模侧最终确认的交付为正式接入版本。

## 4. Home Assistant 接入准备

- **实例待确认。** 由环境提供方确认实例、测试家庭、连接入口、网络可达性、认证方式和测试窗口。凭据由后端运行环境保管，确认隔离的演示会话、允许操作的单盏灯及人工恢复方式。
- **映射待确认。** 后端为每个共享对象登记真实 `entity_id`、读数来源、归一化规则、允许动作、`verification_scope` 和实测记录。以下动作和回读方式均为待验证的接入建议。
- **验收待实测。** 经授权后，先确认灯初始亮态及来源时间，再提交一次模拟任务对应的真机关灯动作。记录指令受理与设备状态观察时间，核对实测关灯、有效 off 回读和页面/3D 一致性。再验证重新读取、重复确认与异常反馈，最后按约定恢复初始状态。

| 共享对象 | 实体映射 | 允许动作及回读方式 |
| --- | --- | --- |
| `entry_door` 玄关门 | 普通门，人工检查点 | 人工确认或稍后核实，回读为本任务人工证据。 |
| `balcony_door` 阳台门 | 门磁实体待确认 | 只读/重新读取。待实测开合映射、状态事件或主动读取、离线和过期。 |
| `living_room_light` 客厅灯 | 首盏灯实体及类型待确认 | 基线测试允许关灯与人工约定的恢复动作，能力及权限待确认。观察实体状态事件或主动读取，核对事件来源、时间和实际灯态。 |
| `bedroom_ac` 卧室空调 | 实体、开关与遥测映射待确认 | 模拟可关机，实机动作待验证。核对设备状态与暖通模式、供电和温度源，验证留家约束后再评估允许动作。 |
| `home_battery` 家庭电池 | 电量实体、保留线配置及备电回路待确认 | 只读。核对百分比、来源、时间及回路归属。 |
| 能源计量 | 表计实体及家庭/购电口径待确认 | 只读。核对 W/kWh、当地日/月边界和数据新鲜度。 |

本轮实机能力为待确认。大户型新增对象在小公寓链路走通后逐项登记，按 v0.5 的能力边界验收。
