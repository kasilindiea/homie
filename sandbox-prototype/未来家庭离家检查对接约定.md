# 未来家庭离家检查对接约定

版本 v0.5 · 适用于房屋建模、前端设计和后端联调

2026-11-14 状态接口增补：移除设备点击/双击播放动作和动作演示按钮，保留点选定位、旋转、缩放及标签模式。动画统一由状态数据驱动；增加供电状态、空调/洗衣遥测以及冰箱冷藏/冷冻分区温度。

2026-11-14 增补：新增单层大户型模板及其房间、智能设备节点。原四个房间、四个任务对象和离家基线保持兼容。新增标识按本文件固定，模型和映射不得另起别名。

三个对话均使用本文件的标识、字段含义和演示数据。需要改动时，先更新本文件并同步另外两边，再调整模型、页面或接口。接口路径、技术栈和相机参数由各侧在联调时确定。

## 0. 产品方向与本轮范围

项目定位为「具有 3D 空间界面的家庭智能中枢」：理解家庭需求、读取状态、生成可确认的跨设备计划，并通过执行回读展示结果。保留两个户型、共享标识与现有前端设计；模型查看器仅作资产和数据适配参考，不替代产品界面。

架构边界为「现有网页/平板终端 → Agent 与业务后端 → Home Assistant/厂商适配层 → 经逐台验证的兼容设备」。当前提供可替换接口和模拟闭环，不代表硬件终端、所有品牌接入或真实控制已经实现。能源管理增强离家场景并可与家庭能源业务关联，但不构成赞助商额外评分承诺，也不代表已经获其设备权限。

本轮只覆盖小公寓 baseline 与大户型单层室内。优先发挥现有电视、空调、洗衣机、冰箱、窗帘节点；不增加柜内查看、冰箱内容物、库存管理、二楼或庭院。

新增演示样例只用于大户型查看器：洗衣机 running/剩余 35 分钟，冰箱冷藏 4.2°C/目标 4°C、冷冻 -17.8°C/目标 -18°C、门已合上，餐厅灯 on，书房灯 off，电视 off，窗帘 open/100%，生活阳台门 closed。全部明确 demo_mode=true，模拟读数 source=device（两扇门磁为 sensor）；不写入模型的静态几何、纹理或 extras。

大户型仍先验收原三步「全屋复位 → 提醒定位玄关 → 点选客厅灯」，再增加洗衣机热点定位与只读运行状态、餐厅灯独立预览等检查。原基线计划不自动增加执行项。新的允许动作和计划规则由后端接入时明确，洗衣机、冰箱、窗帘不能由泛化关机逻辑自动处理。

前后端对本次扩展的共同入口为本节及 `house-modeling/templates/large-flat-128/` 的实际映射、演示样例与交接说明；资产交付不代表真实实体已映射或产品接口已完成联调。

### 1.4 查看器交互与状态动画

保留滚轮指向缩放、右键平移、旋转、全屋复位、房间/设备点选定位和标签模式。删除动作演示按钮及设备双击播放动作的绑定。点击和双击都不得改写状态、人工记录或触发开关动画；只有外部状态快照/增量更新驱动设备视觉。独立查看器可通过「模拟情景数据」选择器注入 fixture，产品前端按其现有设计接入同一数据接口。

- 门 state=open/closed 驱动铰链或推拉扇位置，unknown 保留布局/最后姿态并明确标为未知，不能当作 closed。玄关普通门只接受人工来源的有效证据；改变模型姿态不产生人工确认记录。
- 灯和电视 state=on/off 驱动发光/屏幕渐变。空调 on 时导风片展开、持续送风，off 时收拢、停止气流。unknown 停止活动并标明未知，不伪装成已确认关闭。
- 洗衣机 cycle_state=running 时持续转动；paused/idle/completed/off/error 时停止。未知、离线、过期或电源 unpowered 时停止，状态文字仍区分这些原因。
- state=off 与 power_state=unpowered 是两个事实。关闭但仍通电应显示 off + powered，不得由关闭状态自动推断已断电。
- 计划预览继续只改变虚线覆盖层，不改变当前读数或上述状态动画。发送指令/计划目标也不能提前代替设备回读。

运行时节点仍沿用既有名字：`entry_door__demo_hinge`、`bedroom_ac__demo_blade`、`bedroom_ac__demo_airflow`、`washing_machine__demo_drum`。其中 demo 为历史命名，新版用作状态渲染辅助节点；不新增业务 shared_id、不写回 GLB。原语义根、anchor、focus 保持不动，网格拾取向父链查共享根。

全屋复位只重置镜头与选中；演示复位由数据提供器恢复基线快照，动画再跟随快照恢复，不直接绕过状态接口设置模型。

## 2. 状态字段

### 对象状态

| 字段 | 约定 |
| --- | --- |
| `object_id` | 上表固定标识。 |
| `room_id` | 所属房间。全屋对象为 `null`。 |
| `state` | 枚举按对象解释，门为 `open / closed / unknown`，灯与空调为 `on / off / unknown`。电池数值用 `soc_pct`（0–100 的数或 `null`）表达，对象状态行可省略 `state`。 |
| `source` | `sensor` 门磁读数、`device` 设备读数、`manual` 现场确认。没有有效证据时为 `null`，例如未经核实的玄关门。 |
| `updated_at` | 证据产生时间，使用带时区的 ISO 8601 格式，例如 `2026-11-14T09:11:42+08:00`。无证据时为 `null`。 |
| `availability` | `online / offline / stale / not_applicable`。设备离线或过期时当前状态为 `unknown`，可另传 `last_known_state` 和 `last_known_at` 给页面展示历史读数。人工项使用 `not_applicable`。 |

响应或演示数据集另带 `demo_mode`。模拟门磁仍标记 `source: sensor`，模拟人工确认仍标记 `source: manual`。「待核实」是状态提示，来源栏只表达证据。仅门磁读到 `closed` 时，页面显示「已合上 · 门磁」。上锁如需核实，作为独立人工项。

### 供电与设备遥测

| 对象或字段 | 固定约定 |
| --- | --- |
| power_state | `powered / unpowered / unknown`，独立于 state 和 cycle_state；未提供时为 unknown，不从运行或关闭推断。 |
| bedroom_ac.current_temperature_c | 当前室温，有限数或 null。 |
| bedroom_ac.target_temperature_c | 设备设定温度，有限数或 null；读取字段不代表已授权设置。 |
| bedroom_ac.hvac_mode | `cool / heat / auto / dry / fan_only / off / unknown`。 |
| bedroom_ac.timer_state | `disabled / active / unknown`。 |
| bedroom_ac.timer_remaining_minutes | 非负数或 null；仅 timer_state=active 且有有效数据时展示倒计时，disabled 显示未设置定时。 |
| washing_machine.cycle_state | `off / idle / running / paused / completed / error / unknown`。 |
| washing_machine.program | 工作程序名称或 null，例如棉织物；仅设备报告或明确模拟输入。 |
| washing_machine.phase | `washing / rinsing / spinning / soaking / drying / idle / completed / unknown`，与整机运行状态分开。 |
| washing_machine.remaining_minutes | 非负数或 null；0 是有效值，不等于缺失。由数据更新，不由动画帧自行递减。 |
| washing_machine.current_temperature_c | 当前洗涤水温，有限数或 null。 |
| washing_machine.target_temperature_c | 洗涤程序目标温度，有限数或 null。 |
| kitchen_fridge.door_state | `open / closed / unknown`，整体门读数；不增加未定义的智能门控制能力。 |
| kitchen_fridge.compartments.fridge | 冷藏分区，独立字段如下；对应模型 `kitchen_fridge__upper_door`。 |
| kitchen_fridge.compartments.freezer | 冷冻分区，独立字段如下；对应模型 `kitchen_fridge__lower_door`。 |

冰箱两个分区各自携带 current_temperature_c、target_temperature_c、availability、source、updated_at，必要时携带 last_known_values、last_known_at。温度允许负值，冷冻负温不能被截为 0。单个分区离线只清空该区当前温度，另一分区仍可有效；整机离线则两个分区均失效。旧 temperature_c 最多迁移为冷藏 current_temperature_c，绝不复制为冷冻读数。

数值单位固定：温度为 °C、剩余时间为 min、百分比为 %。对象级 source/updated_at/availability 默认覆盖该对象同批字段；来自不同来源或时间的字段通过 field_meta.<字段名> 单独携带这三项及 unit。实测温度与设定温度不能互相填补。洗衣实际水温无读数时为 null，即使程序设定温度已知。冰箱可携带 anomalies 数组（code、severity、message、source、updated_at）；展示异常不推断已执行关机。

离线/过期的当前枚举归 unknown，当前温度和剩余时间归 null，历史值与最后读数时间单独保留。已知断电时停止运行视觉；若同时收到 on/running 等冲突字段，保留原字段并标记 consistency_warnings，不能把它自动当作执行成功或继续动画。

状态快照带 template_id、demo_mode、objects。适配器提供 replaceSnapshot（全量替换）与 patchObjects（按 object_id 深合并增量）；增量遗漏字段保持原值，显式 null 清空字段。拒绝错误模板、未知对象 ID、错误 room_id 与非有限数值。渲染器只订阅状态，不向设备发送动作。具体 HTTP/WebSocket 路由由后端另定，本阶段不虚构已存在的设备接口。

可复用 fixture 包含：基线、灯未关、门未关、设备已关闭但仍通电、明确断电、空调温度/定时变化、洗衣运行/暂停/完成、冰箱分区温度变化和分区/设备离线。所有模拟对象仍使用正确的 sensor/device/manual 来源，且整体 demo_mode=true。

### 家庭与人工确认

- `user_away` 为 `true / false / null`，表示发起人已出门、未出门或未声明。`occupancy` 为 `occupied / empty / unknown`，表示有住户或宠物留下、无人或宠物留下、尚未确认。用 `retain_room_ids` 记录已知需要保留设备的房间。
- 填写计划中的留家约束与确认本人已经出门是两个动作。人工检查或门磁事件只更新对应的门窗项。留家状态未知时先补问，或保留可能影响住户和宠物的设备。
- 人工记录至少包含 `task_id`、`object_id`、`result` 和 `confirmed_at`。`result` 取 `pending / confirmed_closed / deferred`，确认时记录时间，待核实和稍后核实保留在清单。本次确认仅对本任务有效。

### 计划与执行结果

- 计划携带 `task_id`、`plan_version`。计划项至少携带 `item_id`、`object_id`、`group`、`current_state`、`target_state`、`action`、`reason`、`selected` 及用到的证据。分组使用 `action / keep / manual / check`。只提交选中的 `action` 项执行，空调成为候选时默认不勾选。
- 执行前复核计划版本、留家约束和相关设备状态。条件变化时返回受影响条目供用户重新确认。同一次确认重复提交时复用已有执行结果。
- 每项结果含 `item_id`、`status`，以及可用的回读状态和时间。`status` 使用 `pending / running / awaiting_readback / confirmed / failed / unknown`。指令发出后进入待回读，读到目标状态才确认完成。超时显示「结果待核实」，先刷新状态再决定是否重试。3D 实际状态随设备读数更新，预览高亮单独显示。

| --- | --- | --- |
| `entry_door` | `unknown`，无证据 | 「玄关门待现场确认」。点击提醒聚焦玄关。确认后显示「住户已确认关闭」和确认时间。 |
| `balcony_door` | `closed`，`sensor`，在线 | 显示「已合上 · 门磁」，可作为已核实检查项。 |
| `living_room_light` | `on`，`device`，在线 | 在示例客厅无人时建议关灯。回读 `off` 后更新右栏和 3D 灯光。 |
| `bedroom_ac` | `on`，`device`，在线 | 因猫留卧室而保持运行。改成全员离家且无其他保留规则时，进入关机候选。 |

必验分支包括玄关选择「稍后核实」后仍能执行独立关灯动作，阳台门磁离线后显示当前未知及最后读数，以及确认前状态变化、回读超时和部分失败。演示复位恢复基线对象、人工记录、计划和能源提示。

### 能源备用分支

| 字段 | 示例值 |
| --- | --- |
| `demo_mode` | `true` |
| `timezone`、`meter_scope` | `Asia/Shanghai`、`household_consumption`（家庭总用电） |
| `month_days`、`monthly_limit_kwh`、`month_used_kwh` | 30、300、128（含今日） |
| `daily_reference_kwh`、`today_used_kwh` | 10、12 |
| `soc_pct`、`reserve_pct` | 25、30 |

- 日参考线为「月度上限 ÷ 当月天数」。同一计量口径按家庭当地自然日和自然月统计。如果只有电网购电读数，页面标为「购电预算」，并使用 `grid_import` 口径。
- 今天 12 kWh 首次超过 10 kWh 时提示「比今日参考线多用 2 kWh」。同一自然日重复采样合并提醒。首次超额用从 10 kWh 更新为 12 kWh 的样例验证。月度累计超过 300 kWh 时使用独立的月度超额提示。
- 默认只提醒，可通过「查看省电计划」预览并确认。预授权自动省电只对允许列表内、当前满足条件的非必要设备生效，并检查有效期、留家约束和读数新鲜度。示例允许关闭客厅灯，保留卧室空调。用电超额与低备电量各有触发原因，指向同一设备时合并动作。低备电建议只优先指向已知接入备电回路的负载，电池本身保持只读。

### 能源指标与逐台能力接口

新版快照使用 energy.measurements。每个指标统一携带 value（数或 null）、unit、source、updated_at、availability、data_kind（measured/estimated/simulated）；估算另带 assumptions 与 basis_kind。无有效证据、离线、过期时 value=null，last_known_value 和 last_known_at 可单独保留。不得把估算或模拟值写成实际节能成果。

| 指标键 | 单位 | 含义 |
| --- | --- | --- |
| instant_power_w | W | 同计量口径下的当前功率，不是累计电量。 |
| today_used_kwh | kWh | 家庭当地自然日累计电量。 |
| month_used_kwh | kWh | 当地自然月累计电量，含今日。 |
| estimated_cost | CNY | 示例费用估计；必须列电价、计量口径等假设。 |
| soc_pct | % | 备电电量百分比，不能直接等同于可用续航。 |
| estimated_runtime_minutes | min | 续航估算；注明可用容量、保留线、假设负载等依据。 |

source 可用 meter/storage/calculation/simulator 或 null。data_kind=estimated 且输入为模拟时，basis_kind=simulated。energy 保留 timezone、meter_scope、month_days、monthly_limit_kwh、daily_reference_kwh、reserve_pct；旧 today_used_kwh/month_used_kwh/soc_pct 数值可作为 measurements 的兼容投影，不建立第二个独立真值。

energy.objective 区分 reduce_consumption（减少用电）、reduce_grid_cost（降低购电费用）、extend_backup（延长备电）。低价时段不等于减少 kWh；续航估计也不等于已实现延长备电。alerts 由业务后端或 fixture 提供，渲染层不自己决定关设备。

capabilities 按 object_id 返回：verification_scope（unverified/simulation/physical）、allowed_actions（数组）、supports_delayed_start（布尔或 null）、backup_circuit（connected/not_connected/unknown）、source、updated_at。simulation 只表示模拟器能力，不是实机授权。真实控制只使用 physical 且逐台验证的后端允许动作。未知备电回路不进入低备电动作建议；运行中的洗衣机不能进入通用断电，冰箱不作为普通关机项。预约/错峰只有能力明确、设备当前未运行、截止时间与其他条件满足时才成为候选。

扩展演示输入为「我出门两小时，猫留在主卧，衣服要在晚上六点前洗完」。大户型样例提供可审阅 plan：关闭无人使用的灯/电视，保留主卧空调和冰箱，已运行洗衣机继续完成，玄关待人工核实。预约能力未知时解释不安排预约，不假造按钮或成功结果。小公寓不具有洗衣机/电视空间节点时不虚构这些设备。

快照可带 intent_text 与 context。context.simulation_now 是模拟时钟（带时区 ISO 8601），laundry_finish_by 是洗衣截止时间或 null，room_occupancy 按 room_id 给出 occupied/empty/unknown。这些是业务上下文，不写入 GLB。energy.alerts 的记录包含 alert_id、kind、message、object_ids；kind 可为 daily_budget_exceeded/low_backup，提醒不等于执行动作。

执行状态沿用 pending/running/awaiting_readback/confirmed/failed/unknown。快照中的 execution 和 plan 只供现有任务面板显示；3D 不读取它们的 target_state 来改变实况。awaiting_readback、failed 或只收到 command_accepted 时，实际对象保持最后有效读数；仅新的有效对象读数驱动动画变化。

execution 为数组，每项至少含 item_id、object_id、status，可带 readback_state、readback_at、error；无回读时两项 readback 字段为 null。数据提供器不因 status=confirmed 自动合成对象状态；后端仍应同时交付有效对象读数。

统一调试入口可注入完整 fixture 或增量，必须标明 demo_mode=true。产品控制通过「计划 → 用户确认 → 后端允许动作 → 执行 → 回读」路径，不能调用场景注入来冒充真实控制。

## 4. 交付与联调顺序

前端由 GPT‑6 Astra 负责。当前只在 `frontend/` 做页面设计、状态规格和 3D 区域预留。建模侧确认最终交付后，再开始前端开发、模型嵌入、状态桥接和业务接口接线。

| 顺序 | 负责与交付 | 验收 |
| --- | --- | --- |
| 1. 设计预留与交付准备 | 前端 GPT‑6 Astra 用本文基线细化布局、页面状态和 3D 预留。建模 GPT‑6 Astra 并行修整模型和本地状态适配。后端 GPT‑6.1 Sol 可先准备字段样例。 | 页面规格明确 3D 区域、加载状态和交互边界。共享标识和基线数据按本文核对。 |
| 2. 开发并接入模型 | 建模侧确认 GLB、实际节点映射、默认视角、运行时模块和状态适配版本后，前端开始开发，并先用小公寓接入。 | 能复位到全屋，从提醒定位玄关，并通过客厅灯热点打开同一设备详情。计划高亮和实况更新相互独立。 |
| 3. 联通离家任务 | GPT‑6.1 Sol 交状态读取、计划、人工确认、执行、回读与复位的接口说明和模拟样例，协同前端联调。 | 跑通基线、全员离家、玄关跳过、门磁离线、状态变化、部分失败和超时。 |
| 4. 接入能源分支 | 后端补用电数据、去重和授权样例，前端接预算、提醒、预览及暂停入口。 | 能复现超额 2 kWh、同日提醒合并、保留设备不被省电动作关闭。 |
| 5. 可选真机验证 | 有 Home Assistant 环境和实体后，先用一盏灯核对读数、动作和回读。 | 页面、模型与设备状态一致，演示明确标出模拟与真实来源。 |

## 5. 现有前端样例的适配点

`app/data.js` 已使用上述房间和对象标识。它内部用 `id`、`room`、`family.away`、`family.occupants` 和驼峰能源字段，可在接入时映射到本文共享字段。它的电池卡目前挂在阳台，接口按全屋对象返回。现有时分秒字符串用于页面显示，联调数据使用完整时间戳。现有玄关待核实样例标记为 `manual`，对接时等到现场确认后再赋予人工来源。以上为联调时的适配事项。
